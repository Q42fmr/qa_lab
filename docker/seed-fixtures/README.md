# Зразки фікстур для MOCK_MODE

Дві мінімальні «вітки», якими `entrypoint.sh` засіває `fixtures/`, якщо та
тека порожня.

## Навіщо

Без `GITLAB_TOKEN` лаба вмикає `MOCK_MODE` і читає вітки з `fixtures/<назва>/`,
а `MockClient` навіть **комітить назад у теку**. Тобто повний робочий цикл —
Sync → перевірки → Preview → Apply — ганяється **офлайн, без жодного токена і
без доступу до GitLab**. Це головний смоук-тест образу: він перевіряє реальний
шлях, а не «сервер відповів 200».

## Чому тут, а не прямо в `fixtures/` — і чому назва саме така

У `.gitignore` вже стоїть `fixtures/` — розробник тримає там свої робочі
знімки. Ми свідомо **не чіпаємо той файл** (він легко конфліктує при злитті),
тому зразки лежать тут, а entrypoint копіює їх лише коли `fixtures/` порожня.
Чужі фікстури не перетираються ніколи.

Назва **`seed-fixtures`, а не `fixtures`** — через різницю в семантиці
ігнор-файлів, на яку легко наступити:

| | патерн `fixtures/` матчить |
|---|---|
| **git** | теку з такою назвою на **будь-якій глибині**, тобто й `docker/fixtures/` |
| **docker** | лише `fixtures/` у корені контексту |

Тобто `docker/fixtures/` збиралося б в образ нормально, але **мовчки не
потрапляло б у коміти**: `git add` пропускав би теку без жодного попередження.
Саме так і сталося при першій спробі — звідси й назва.

## Склад

| Вітка | Що це |
|---|---|
| `demo-clean` | здорова вітка: меню на місці, `{{DOMAIN}}` у пошті, форма без `action`/`method`, робоча фавіконка, нормальні контрасти. Еталон — на ній чеки мають мовчати |
| `demo-broken` | навмисні дефекти під конкретні чеки (нижче) |

### Дефекти в `demo-broken`

| Чек | Дефект | Спрацювань |
|---|---|---|
| `wrong_literal` | `info@{{DOMAIN_NAME}}` — бренд без зони розкриється в неіснуючу адресу | 5 |
| `contacts` | `support@larkfield-partners.com` — реальний домен у пошті замість `{{DOMAIN}}` | 2 |
| `empty_href` | `<a href="">Services</a>` у меню | 2 |
| `media_integrity` | наслідок мертвої фавіконки: `/favicon.ico` у вітці немає | 2 |
| `forms` | `<form action="/send.php" method="post">` в `index.php` (є автофікс) | 1 |
| `favicon` | `<link rel="icon">` веде на файл, якого немає | 1 |
| візуальні | `.hero-sub` — `#c9ced6` на білому, зміряний контраст **1.58:1** | 2 (desktop + mobile) |

Заміряно на зібраному образі: `demo-broken` → **14 error**, `demo-clean` → 1.

Той єдиний на здоровій вітці — `php_scripts`: він шукає канонічні php-блоки
(init / пікселі / конверсія), яких у демо-вітці немає й не мусить бути.
Чек лежить у групі **`review`**, тобто в UI вимкнений за замовчуванням —
у нормальному прогоні `demo-clean` мовчить повністю.

Зразки навмисно маленькі: їхнє завдання — довести, що механіка працює
наскрізь, а не замінити реальний корпус.

## Як користуватись

```bash
docker compose -f docker-compose.dev.yml up
# у .env: MOCK_MODE=1 (або просто порожній GITLAB_TOKEN)
# у сайдбарі додати вітки: demo-clean, demo-broken
```
